## 一、目标需求

**用户想要的效果（类似知更AI）**：
```
外部客户（任何微信用户）
  → 添加/进入某个企业微信（客服）
  → 在微信 APP 里直接发消息
  → 机器人自动检索知识库回复（7×24）
```

前端已实现为管理界面（管理员增删文档），知识库 RAG 管线已就绪。

---

## 二、方案调研全景（重要结论）

### 方案 1: 企业微信自建应用 + 消息回调  — ❌ 不适用

| 项 | 值 |
|---|---|
| 能力 | 企业内部员工在工作台使用，API 收发消息 |
| 致命缺陷 | **仅企业内部员工可用**，外部客户无法访问 |
| 现状 | ✅ 代码已写完（见 §四），但方案本身不满足需求 |

### 方案 2: 企业微信「微信客服」(Kefu)  — ✅ 唯一官方合规方案

| 项 | 值 |
|---|---|
| 能力 | 客户扫码/点链接 → 微信内客服会话 → API 收发消息 → 自动回复 |
| 客户体验 | 扫个码，在微信里和一个"企业"聊天，发消息就有回应 |
| 认证要求 | 需企业微信完成**企业认证**（现实瓶颈） |
| 结论 | **技术上唯一能实现"客户微信发消息→自动回复"的官方通道** |

### 方案 3: 微信 ClawBot 插件 (iLink / OpenClaw)  — ❌ 定位不符

| 项 | 值 |
|---|---|
| 是什么 | 微信官方 2026-03 推出的插件（"龙虾插件"），绑定你的 OpenClaw AI 智能体 |
| 致命缺陷 | **"其他用户无法添加或查看"** —— 只能自己私聊自己的 AI 助手，不是对外客服入口 |
| 附加限制 | 灰度推送（无入口说明未开放）；需部署 OpenClaw；不支持群聊；不支持 AI 主动推送 |
| 结论 | 定位是"个人 AI 助理"，不是"对外客服"，**走不通** |

### 方案 4: 个人微信 Hook 框架（WeChatFerry 等，知更AI 同类路线）  — ⚠️ 高风险

| 项 | 值 |
|---|---|
| 是什么 | DLL 注入微信 Windows 客户端，拦截收发消息（开源） |
| 优点 | 微信号可被加好友，体验最接近"客服微信号" |
| 致命缺陷 | ① Hook 注入本身可被微信识别，社区统计**封号率 >80%**；② 微信更新即失效；③ 商业场景封号=客户联系方式全断 |
| 行为风控 | 微信会检测回复速度异常、24h在线、频率、文本特征；知更AI 的"延迟3-8秒/限频"只是行为伪装，消除不了 Hook 本身 |
| 知更AI 澄清 | 知更AI 是商业闭源软件，"底层封装微信协议监听"。**与 WeChatFerry 只是"技术路线同源"（都是个人微信非官方 Hook），无证据证明代码同源** |
| 结论 | 能用但随时可能封号。**不推荐商业客服使用** |

### 方案 5: 自建应用 + 客户联系授权  — ⚠️ 能力被误读

| 项 | 值 |
|---|---|
| 能做什么 | 读取企业成员的外部客户名单、客户群、标签（**数据管理**） |
| 不能做什么 | **无法自动回复客户消息** —— 外部联系人消息收发，官方不开放自动回复 API（会话存档仅只读，供合规审计） |
| 结论 | 用户从网上查到"自建应用授权可获取客户联系数据"属实，但那是**读客户数据**，不是**收发消息**，补不上自动回复 |

---

## 三、关键结论（技术事实）

1. **微信里不存在"搜索添加企业微信"的交互** —— 企业微信不像微信号可被搜索添加。对外只有"扫码/点链接"两条通道。
2. **能自动回复客户微信消息的官方通道只有"微信客服"** —— 外部联系人（加好友）的消息自动回复被企微封死。
3. **所有个人微信 Hook 方案（WeChatFerry/知更AI 等）都是违反微信条款的非官方接入**，行为伪装只能降低概率、无法消除 Hook 本质风险。
4. **唯一现实瓶颈：微信客服需要企业认证**。未认证则不可用或受限。

## 四.5、微信客服（Kefu）版实现 — ✅ 已实现

> 2026-08-03 追加：确定走「微信客服」官方通道后，在自建应用版基础上改造，代码完成并全部测试通过。

### 工作机制（回调通知 + 主动拉取，与自建应用版差异大）

```
客户（微信用户）扫码 → 微信里客服会话 → 发消息
   │
   ▼
企微推送加密 XML 回调（Event=kf_msg_or_event）
   │  只含 Token(10分钟有效) + OpenKfId，【不含消息正文】
   ▼
服务器解密 → 调 kf/sync_msg 主动拉取消息内容（增量游标 cursor）
   │  过滤 origin=3（微信客户发送）的文本消息
   ▼
逐条走 RAG → LLM 生成 → 调 kf/send_msg 回复
```

### 与自建应用版的关键差异

| | 自建应用版 | 微信客服版 |
|---|---|---|
| 回调内容 | 消息正文 XML | 事件通知 XML（无正文） |
| 获取消息 | 直接解析 | `kf/sync_msg` 主动拉取 |
| 发送接口 | `message/send` | `kf/send_msg` |
| 客户 ID | 企微 user_id | `external_userid` |
| Secret | 应用 Secret | 微信客服 Secret |
| 记忆 thread | `wecom_{user_id}` | `wecom_kf_{external_userid}` |

### 官方限制（代码已遵守）
- 仅可在客户最后消息后 **48 小时内**回复，且最多 **5 条**
- 回调 Token **10 分钟**有效（收到回调立即拉取）
- `sync_msg` 只能拉 **3 天**内消息（游标增量 + msgid 去重兜底）
