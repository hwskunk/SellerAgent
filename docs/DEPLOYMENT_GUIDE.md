## 一、这套系统是干什么的

**SellerAgent** 是一套「销售 AI 客服」系统：

- **给客户**：微信扫码进入企业微信客服 → 发消息 → AI 基于你们的知识库自动回复（7×24）
- **给管理员**：网页后台管理知识库（上传文档）、查看对话、管理会话

工作流程：
```
外部客户（个人微信）扫码 → 发消息
  → 企业微信推送回调到服务器
  → 服务器检索知识库 + AI 生成回复
  → 自动回复给客户
```

## 二、你需要准备的东西

| 东西 | 说明 | 必须 |
|---|---|---|
| **服务器**（阿里云/腾讯云，Linux） | 跑这套系统 | ✅ |
| **域名** | 已备案，备案主体与企微认证主体一致 | ✅ |
| **企业微信** | 已完成「企业认证」（300元/年） | ✅ |
| **DashScope API Key** | 阿里云灵积，AI 的钥匙 | ✅ |
| **HuggingFace Token** | 文档解析用（免费申请） | 建议 |
| **本地电脑** | 打包代码、上传文件、转换文档 | ✅ |

> 两种部署档位（重要）：
> - **大服务器**（内存 ≥6G）：能在网页直接上传 PDF/XLSX 解析，最方便
> - **小服务器**（内存 ≤2G）：只能在网页上传 Markdown，PDF 需先在本地转换（见第六、七章）

## 三、部署代码到服务器

以宝塔面板（BT Panel）操作为例。

### 3.1 拿到代码包

代码包是 `SellerAgent-deploy.zip`。两种方式：
- 从本项目目录直接拿这个 zip
- 或者从 GitHub 仓库 `feat/wecom-integration` 分支下载

### 3.2 上传并解压

1. 宝塔 → **文件** → 进入 `/root/` 目录
2. 上传 `SellerAgent-deploy.zip`
3. 右键 → 解压到 `/root/SellerAgent`（覆盖旧文件）

### 3.3 配置 .env（最关键，出错率高）

1. 宝塔 → 文件 → 打开 `/root/SellerAgent/.env`
2. 填入你的真实值。**注意三条铁律**：
   - 每行必须是 `KEY=值`（**等号**，不是冒号）
   - **不要写行内注释**（`KEY=值   # 注释` 会被误读）
   - 只填必填项，其他留空即可

```bash
# AI 的钥匙（必填）
DASHSCOPE_API_KEY=你的阿里云灵积Key

# 文档解析用（建议填）
HF_TOKEN=你的HuggingFace Token

# 企业微信接入（见第五章，先配好企微再填）
WECOM_CORP_ID=企业ID
WECOM_APP_SECRET=自建应用Secret
WECOM_KF_SECRET=
WECOM_TOKEN=回调Token
WECOM_ENCODING_AES_KEY=43位密钥
WECOM_OPEN_KFID=

# 小服务器省内存（可选，见第六章）
# DOCLING_PREWARM=false
```

### 3.4 安装依赖

宝塔 → **终端**（或 SSH），执行：

```bash
cd /root/SellerAgent
./venv/bin/python3 -m pip install -r requirements.txt
```

> ⚠️ 以后每次更新代码，如果 `requirements.txt` 变了，都要重新跑这一步，否则会报缺依赖。

### 3.5 启动服务

```bash
cd /root/SellerAgent && bash start.sh
```

看到 `[SellerAgent] 启动完成` 就说明起来了。**如果不想让它占住终端**，用 screen：

```bash
screen -S selleragent
bash start.sh
# 按 Ctrl+A 然后 D 离开（服务继续后台跑）
# 以后重新进入：screen -r selleragent
```

## 四、域名反向代理与端口

目标：让 `https://你的子域名` 能打开这套系统，并把企微回调转发到服务器。

### 4.1 DNS 加 A 记录

登录**域名所在阿里云账号**的 DNS 控制台，**新增一条** A 记录（不要动现有的）：

```
类型: A        主机记录: kf      记录值: 服务器公网IP
```

> 子域名（如 `kf.你的域名`）复用一级域名的备案，不用单独备案。

### 4.2 阿里云安全组放行端口

阿里云控制台 → 你的服务器 ECS → **安全组 → 入方向规则**：
- 确认已有：TCP **80**、TCP **443**、TCP **8080**（来源 `0.0.0.0/0`）
- 没有就添加

### 4.3 宝塔防火墙放行

宝塔 → **安全 → 防火墙** → 放行 **80、443、8080**。

### 4.4 宝塔添加站点 + 反向代理

1. 宝塔 → **网站 → 添加站点** → 域名填 `kf.你的域名`（只绑子域名）
2. 站点设置 → **反向代理** → 目标 `http://127.0.0.1:8080`，路径 `/`
3. 保存

### 4.5 申请 SSL 证书（强制）

1. 站点设置 → **SSL** → 申请 **Let's Encrypt 免费证书**
2. 勾选 **强制 HTTPS**

> ⚠️ 必须申请证书。**企微回调要求 HTTPS**，HTTP 会回调失败。

### 4.6 验证

浏览器打开（手机、电脑都行）：

```
https://kf.你的域名/api/wecom/callback?echostr=test123
```

页面显示 `test123` = ✅ 反代和 HTTPS 全部通了。

## 五、接入企业微信（微信客服）

### 5.1 前置条件（缺一不可）

- 企业微信**已完成企业认证**（否则只有 100 客户上限，无法商用）
- 域名**已备案**且备案主体 = 企微认证主体（否则"域名主体校验未通过"）

### 5.2 创建微信客服账号

1. 企微管理后台 → **客户联系 → 微信客服 → 客服账号**
2. 点「添加」，创建客服账号（名字随便，如"在线咨询"）

### 5.3 创建自建应用

企微后台 → **应用管理 → 自建 → 创建应用** → 拿到 **Secret**（填进服务器 .env 的 `WECOM_APP_SECRET`）

### 5.4 设置「API 接收」并关联自建应用（关键三步，缺一不可）

按这个顺序做（这是消息能进你们系统的核心）：

1. **微信客服 → API 管理 → 设置「API 接收」** → **选择你的自建应用**
   - 把客服消息的接管权交给自建应用，否则消息走不到你们系统
2. **自建应用 → 接收消息配置** → 设置回调 URL：
   ```
   https://kf.你的域名/api/wecom/callback
   ```
   填 **Token**（自己填随机字符串）、**EncodingAESKey**（点生成，43 位）
   → 两个都记下来，和服务器 .env 里 `WECOM_TOKEN` / `WECOM_ENCODING_AES_KEY` **一字不差**
3. **自建应用 → 可信 IP** → **添加服务器公网 IP**
   - 不加会报 `errcode 60020`（ip 不允许访问），消息拉不下来也发不出去

> 回调 URL 验证通过后，记得再点 **「完成 / 开始使用」**（只验证通过不算真正生效）。

### 5.5 添加接待人员

1. 客服账号 → **接待人员** → 把任一企业员工添加进去
2. 手机下载**企业微信 App**（不是个人微信）→ 登录 → 接受接待邀请

> 接待人员是"后台接客的角色"，AI 自动回复替代了真人。**客服账号必须有接待人员才能接客**。

### 5.6 测试

1. 客服账号 → 生成**二维码** → 用**个人微信**扫码
2. 发一条消息，比如"你们怎么收费？"
3. 看服务器日志，应该依次出现：
   ```
   [KF] 收到回调: open_kfid=wkXXX...
   [KF] 客户消息: 客户ID → 你们怎么收费？
   [KF] 回复成功: 客户ID
   ```
4. 客户微信里收到 AI 回复 = ✅ 上线成功

### 5.7 客户对话记忆（独立窗口）

每个客户在微信客服里都有**独立、连续的对话窗口**：

- **不同客户之间完全隔离**：A 客户的对话历史、上下文，B 客户看不到也继承不了
- **同一客户内对话连续**：客户问"你们怎么收费"→ 再问"那有优惠吗"，AI 记得上一句能接上
- **客户隔几天回来**：只要客户没被移出企业外部联系人，对话窗口还在（存于服务器 SQLite）

> 实现方式：每个客户一条独立线程（`wecom_kf_{external_userid}`），复用系统的记忆机制（最近 10 轮完整保留 + 更早的自动蒸馏成总结）。每个客户全程是一个连贯的销售对话，互不串台。

## 六、知识库：文档怎么进系统（两档方案）

系统按你服务器内存大小，选一种方式给知识库灌文档。

### 6.1 大服务器（内存 ≥6G）：在线直接上传 ✅ 最方便

1. 打开网页后台 `https://kf.你的域名`
2. 右侧 **知识库** 面板 → **上传文件**
3. 直接传 PDF / XLSX / DOCX / PPTX / 图片，服务器自动解析入库
4. 传完网页对话里测一下能不能答

### 6.2 小服务器（内存 ≤2G）：本地转换后上传

> 原理：服务器端 Docling 解析要占 ~5GB 内存，小服务器扛不住。
> 改在**本地**把 PDF/XLSX 转成 Markdown，服务器只收 .md（.md 直接读文件，不占内存）。

**服务器端设置**：

1. 宝塔打开 `/root/SellerAgent/.env`，加一行：
   ```bash
   DOCLING_PREWARM=false
   ```
2. 重启服务：
   ```bash
   pkill -f "app:app"; sleep 1; bash start.sh
   ```
3. 现在服务器常驻内存从 ~6GB 降到 **~1-2GB**

**每次要加文档时**：

1. 本地用转换工具把 PDF/XLSX 等转成 `.md`（见第七章）
2. 网页后台 → 知识库 → 上传这个 `.md` 文件

> ⚠️ 小服务器如果非要直接传 PDF，会上传失败（内存不够）——所以 PDF 一律本地转。

## 七、本地文档转换工具

配套提供了一个**独立于项目的转换工具**（在 `DocConvertTool/` 目录）：

```
DocConvertTool/convert_to_markdown.py
```

它把 PDF / XLSX / DOCX / PPTX / HTML / 图片 解析成 Markdown，方便小服务器方案使用。

### 7.1 首次准备（一次就好）

1. 电脑装 Python 3.10+（去 python.org 下载，勾选"Add to PATH"）
2. 打开命令行，安装依赖：
   ```bash
   pip install docling
   ```

### 7.2 使用

```bash
# 转换单个文件 → 输出到 ./output_markdown/
python convert_to_markdown.py 产品手册.pdf

# 转换多个文件
python convert_to_markdown.py a.pdf b.xlsx c.docx

# 转换整个文件夹（自动跳过不支持的文件）
python convert_to_markdown.py ./我的文档/ -o ./转换结果/

# 指定输出目录
python convert_to_markdown.py 产品手册.pdf -o ./converted/
```

输出：与输入同名的 `.md` 文件，在输出目录里。**把生成的 .md 上传到服务器知识库即可。**

> 首次运行要下载 OCR 模型，耐心等几分钟；后续就快了。

## 九、常见问题排查

### 回调地址验证失败 / "openapi回调地址请求不通过"

| 检查项 | 说明 |
|---|---|
| 用了 HTTPS 吗？ | 必须 HTTPS，HTTP 不行 |
| URL 带路径了吗？ | 必须是 `https://域名/api/wecom/callback`（有 `/api/wecom/callback`） |
| Token 一致吗？ | 企微后台填的和 .env 的 `WECOM_TOKEN` 必须一字不差 |
| EncodingAESKey 一致吗？ | 同上，且必须 43 位 |
| 服务器 .env 填了吗？ | 改了 .env 要重启才生效 |
| 点"完成/开始使用"了吗？ | 只验证通过不算生效 |

### 客户发消息没回复 / 没日志

| 检查项 | 说明 |
|---|---|
| 设「API 接收」选对自建应用了吗？ | 5.4 第 1 步，漏了消息走不到系统 |
| 回调 URL 配了吗？ | 5.4 第 2 步，漏了收不到事件 |
| 可信 IP 加了服务器公网 IP 吗？ | 5.4 第 3 步，漏了报 60020 |
| 接待人员接受邀请了吗？ | 企业微信 App 里点接受 |
| 回调"已启用"了吗？ | 回 API 管理看状态 |

### 上传 PDF 显示"上传失败"

| 场景 | 处理 |
|---|---|
| 服务器存储满了 | 宝塔看磁盘，清理（模型缓存/pip缓存/旧日志） |
| 小服务器内存不够 | 改本地转换方案（第六章、第七章） |
| 传 .txt/.md 也失败 | 服务器代码/依赖有问题，查日志 |

### 服务器内存/磁盘

- 正常占用：预加载时 ~6GB（大服务器），关预热后 ~1-2GB（小服务器）
- 磁盘建议预留 5GB；`torch`、`sentence-transformers` 用不上的话可卸载省 2-3GB

### 客户收到"没有找到相关答案"而不是知识库答案

- 可能是企微**内置机器人**在回复 → 关掉内置智能回复/知识库机器人，让消息走你们系统
- 或者服务器知识库**没传对应文档** → 网页后台传文档，测一下
